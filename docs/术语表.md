# 专业术语表（生物医学）

## 一、它解决什么问题

机器翻译「认得词，但不认行话」。实测这次引擎的原始输出：

| 英文 | 引擎裸译 | 应该译成 |
|---|---|---|
| type strains | 类型菌株 | **模式菌株** |
| clades | 花纹 | **进化支** |
| psoriasis | 多病病人 | **银屑病** |
| in silico | 硅酸盐 | **计算机模拟** |
| hazard ratio (HR) | 危险比率 | **风险比** |
| GenBank | 基因银行 | **GenBank**（保留原文） |

术语表就是把这些「行话」固定下来的地方。打开后同一批句子变成：
`模式菌株` / `进化支` / `银屑病` / `计算机模拟` / `风险比`。

## 二、它怎么做到的（重要，决定了你能怎么用）

**没有采用「先把术语换成占位符、译完再换回来」** —— 实测这个模型会把占位符译烂
（`ZXQ12` → `ZQQ12`），也会把塞进英文句里的中文吃掉（`All 分支 of the tree`
→ `树上的所有 XXX`）。那条路不可靠。

实际做法是 **译后校正 + 自动标定**：

1. 术语表给出「英文 → 规范中文」；
2. **首次使用时**，程序让引擎把每条术语**裸译一次**，把它的错误译法记下来
   （130 条约 16 秒，结果缓存在数据目录，术语表改了才会重算）；
3. 翻译整句后，**若英文原句里出现了该术语**，就把译文里那个错误译法替换成规范译法。

第 3 步为什么要看英文原句：错误译法可能是别处的正常用词
（比如 `clades` 被译成「花纹」，而「花纹」在别的句子里可能是对的）。
有了英文侧的触发条件，替换就是定点、安全的。

## 三、怎么加词

术语表就是一个文本文件，**用记事本就能改**：

```
assets/glossary/biology.tsv
```

在程序里点「打开术语表」可直接定位到它。格式是 **Tab 分隔的四列**：

```
英文 <Tab> 规范中文 <Tab> 备注（可空） <Tab> 已知错误译法（可空，分号分隔）
```

例如：

```
type strain	模式菌株	分类学	类型菌株
clade	进化支	系统发育	花纹;分支群
psoriasis	银屑病	皮肤病	磷酸盐;多病病人
```

规则：

- **分隔符必须是真正的制表符（Tab）**，不是空格（Excel 里请"另存为制表符分隔的 txt"）
- 以 `#` 开头的是注释行，不生效
- 英文匹配**不区分大小写**，并自动兼容复数（+s / +es）
- 第 4 列可以留空——程序会自动标定出引擎的错误译法；这一列是给
  「我已经知道它错成什么、想立刻生效」的情况准备的
- 改完保存，**重开程序**即可，不需要重新打包

## 四、边界：它做不到什么

- **只覆盖表里有的术语**。表里没有的词，仍然按机器翻译的样子出来。
  实测 `confidence interval` 裸译恰好正确，但整句里被译成「置信间隔」——
  这种「换个上下文就变」的情况，靠自动标定抓不全，需要你看到后在
  第 4 列补一条（本表已经补了这条）。
- **不去猜同义词**。表里写 `type strain`，句子里出现的是 `type strains` 能命中；
  但出现 `type culture`、`type material` 就要另加一行。
- **不做语法改写**。它只替换词，不改语序。所以译文可能仍是「机翻腔」，
  只是术语对了。
- **不会把错译变成好文章**。术语准确 ≠ 译文通顺。对外交付仍建议人工过一遍。

## 六、关掉它

- 界面上取消勾选「使用专业术语表」
- 命令行加 `--no-glossary`

关掉后回到引擎原始输出（便于对比术语表的效果）。
